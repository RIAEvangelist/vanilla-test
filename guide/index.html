Get started

One suite. Two runtime adapters.

Keep assertions in a host-neutral module. Node and the browser each import that same module and decide what a failed result means for their environment.

Install and confirm the runtime

vanilla-test v2 requires Node.js 22.12 or newer and uses native ES modules. Install it as a project dependency:

npm install vanilla-test

If your project does not already use ESM, add "type": "module" to its package.json. No compiler or test-specific file transform is required.

Create the shared suite

Export a default or named run() function. Return the result from report() so any host can determine success without reading console output.

import VanillaTest from 'vanilla-test';

export default async function run() {
    const test = new VanillaTest();

    test.expects('addition preserves the total');
    try {
        test.compare(1 + 2, 3);
        test.pass();
    } catch (error) {
        console.error(error);
        test.fail();
    }
    test.done();

    return test.report();
}
Lifecycle invariant

Every expects() begins one active test. Decide it with pass() or fail(), then call done() before starting another test or reporting.

Add the Node adapter

The shared core does not set a process exit code. A thin Node entry translates the frozen result into the convention used by shells and CI:

import run from './shared-test.js';

const result = await run();
process.exitCode = result.ok ? 0 : 1;
node ./test/node.js

Add the browser adapter

Browsers resolve package specifiers with an import map. Serve the project over HTTP; a file: URL is not an equivalent Web origin.

<!doctype html>
<html lang="en">
<head>
    <meta charset="utf-8">
    <script type="importmap">
    {
        "imports": {
            "vanilla-test": "/node_modules/vanilla-test/index.js",
            "ansi-colors-es6": "/node_modules/ansi-colors-es6/index.js",
            "strong-type": "/node_modules/strong-type/index.js"
        }
    }
    </script>
</head>
<body>
    <p data-status>Running…</p>
    <script type="module">
        import run from './shared-test.js';
        const result = await run();
        document.querySelector('[data-status]').textContent =
            result.ok ? 'Passed' : 'Failed';
    </script>
</body>
</html>

The coverage CLI supplies package import defaults for its own harness. Use chrome.imports only for additional specifiers or deliberate overrides.

Add native coverage

Once the shared entry runs in both hosts, point vanilla-test.config.json at it and choose the project-owned files to measure. Node and Chrome reports remain independent.

npx vanilla-test coverage all

Configuration is strict: unknown keys, missing files, escaping paths, empty include scopes, and invalid thresholds fail before a collector runs.
